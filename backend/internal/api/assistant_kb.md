# Agent Synapse 平台知识库

> 本文件是右下角「智能助手」的知识底座。助手必须严格依据本文档回答平台相关问题，不得编造未列出的口径。

## 一、平台定位
- Agent Synapse 是面向 Agentic RL 的诊断平台，相当于 Agent 的「体检中心」。
- 通过 OpenTelemetry 链路埋点，逐次会话用规则评估五项客观体征（执行规整、工具稳定、重复空转、资源开销、调度编排），再叠加 GPT-5.5 的六项语义体验评测，并把异常归堆。
- 三个菜单按「由远到近」构成下钻链路：
  - 大盘（首页）：整体趋势 + 5 维健康度 + 高风险 session 排行，回答「这周 Agent 状态怎么样」。
  - 明细（session 详情）：单次会话完整体检报告（DAG / 5 维 / 异常清单 / 质量评估），回答「这个 session 错在哪一步」。
  - 异常（聚类）：把命中相同异常标签（failed_label）的 session 归堆看共性，回答「哪类问题正在变多」。注意：异常不是 AI 自动聚类，而是按 failed_label 做的简单归堆。

## 二、核心概念：会话三层结构
- Session（会话）：用户和 Agent 的一次完整对话 = 一次 trace，含一个根 span。
- Turn（对话轮次）：用户问一句、Agent 答一句算一轮 = 一组 user→assistant 消息对。
- Step（执行步数）：Agent 一次思考 + 调工具算一步 = 一次 LLM call 加紧随的 tool calls（描述性指标，不评判好坏）。
- Span（步骤埋点）：步骤里每一个具体动作 = OpenTelemetry 链路上最小单元。
- 区别：对话轮次 = 用户问了几次；执行步数 = Agent 自己思考了几次（用户问 1 次但 Agent 可能内部思考 7 步）。

## 三、5 维健康度（规则维度，看客观执行信号）
- 执行规整（response）：执行模式是否规整完成（纯客观结构信号）。不及格 = 没走完轨迹（无答复/截断/工具意图未落地/规划缺失）。
- 工具稳定（stability）：真实工具调用最终成不成功。不及格 = 没办成事。无真实工具调用时 N/A。
- 重复空转（thinking）：是否反复空转或无效循环。不及格 = 反复踩坑（空转/串行重试/重复编辑）。
- 资源开销（resource）：Token 用得省不省。单轮 Token ≤ 76k 满分。
- 调度编排（orchestration）：真实工具调度是否多样高效。无真实工具调用时 N/A。
- 易混淆：工具稳定看后果，调度编排看模式；两者都只在发生过真实工具调用时适用，纯聊天 session 置灰不参与综合分。

### 健康度分档（大盘/明细/异常颜色一致）
- ≥ 85 健康（绿）；70–84 一般（橙）；50–69 风险（紫）；< 50 严重（红）。

### 健康度子项打分口径
- 执行规整：100 − 无答复35 − 截断25 − 工具意图未落地25 − 思考冗余10 − 缺少规划10 − 规划偏离10 − 测试残留5。纯客观结构信号，不再计算耗时体感分（耗时是否合理交给 GPT「效率体感」）。
- 工具稳定：无真实工具调用时 N/A；否则基于 tool 失败率 + 根 span 退出状态，调用失败时硬封顶 50。
- 重复空转：100 − 空转(每步10，上限30) − 串行重试(同名工具连续 ≥3/5/7 次扣 10/20/30) − 重复编辑(同文件 ≥3 次 −20)。
- 资源开销：100 × (1 − max(0, tokens − 76k) / 76k)。
- 调度编排：无真实工具调用时 N/A；否则按多样性 unique/total：≥0.6→100 / ≥0.4→85 / ≥0.25→70 / 否则 50。串行重试已归「重复空转」，此处不重复惩罚。

## 四、指标口径手册（权威口径）

### 耗时类
- E2E 耗时 = root_span.end_time − root_span.start_time（来源 OTel root span）。
- E2E P95 = percentile(durations, 0.95)，统计范围为当前时间窗内全部 session。
- E2E P50 = percentile(durations, 0.50)，同上。
- 关键路径耗时 = DAG 最长串行链总和（DFS 求 max serial chain duration）。
- 关键路径占比 = critical_path / e2e。占比 > 80% 说明串行瓶颈。

### P50 / P90 / P95 时间窗口径（重要）
- 时间窗是动态的：若 URL 携带 start_time 和 end_time（通常从列表页透传），则以该窗口为准；若缺失，则回退为该 session 发生当天整天（00:00–23:59）。
- 注意：后端用于定位 session 详情的 ±2 小时窗口仅用于数据检索，不作为 P50/P90 的基线统计窗口。

### 成本类
- 累计 Token = Σ(input_tokens + output_tokens)（来源每个 LLM span 的 attributes）。
- 总成本($) = total_token × $1.5 / 1M。单价为占位估算，不区分 input/output 实际单价，仅用于横向对比，非财务真账。

### 步数类 / 执行效率
- 执行效率（轨迹级健康）= has_final_answer && !truncated && no_op_streak<3 && !tool_intent_without_execution。
- 执行效率健康（绿）= 有最终答复 && 未截断 && 无连续空转 && 工具决策可落地。
- 轨迹异常（红）= 无最终答复 || 被 max_steps 截断 || 连续空转≥3 || 工具意图未落地。
- effective_rounds（有效轮次）：剔除框架内部合成 prompt（工具回填/转义自检/续接/重试/标题生成等）后的真实用户轮次数。GPT 评测卡片中证据胶囊的步号必须与 effective_rounds 严格一致。

### 异常标签枚举（failed_label）
- 轨迹异常：无答复/截断/工具意图未落地 → 归属「执行规整」。
- 上下文超限：单次 LLM 调用 token 超出模型上下文窗口 → 归属「资源开销」。
- 执行失败：根 span 异常退出/任务未完成 → 归属「工具稳定」。
- 出现死循环：同一工具连续调用 max_serial_run ≥ 阈值 → 归属「重复空转」。

## 五、GPT-5.5 语义体验评测（LLM-as-Judge，看语义体验）
- 规则维度看客观执行信号，GPT 看语义体验，两者严格互斥避免双重惩罚。
- 综合健康度 = 规则 50% + GPT-5.5 50%（GPT 缺失时回退规则 100%）。
- GPT 总分不是 6 项平均分，而是加权：问题解决×30% + 意图匹配×18% + 效率体感×15% + 用户情绪×15% + 可执行性×12% + 幻觉风险×10%。
- 六维含义与判定边界：
  - 问题解决（最多 30 分）：用户核心问题是否真正闭环。声称完成但无执行证据视为未真正解决。
  - 意图匹配（最多 18 分）：回答是否围绕用户真实诉求，是否答非所问/偏离最新追问。
  - 效率体感（最多 15 分）：结合任务难度，耗时/步数是否合理（难度由 GPT 语义判断，规则侧不算）。
  - 用户情绪（最多 15 分）：只看用户表达的情绪词（感谢/崩溃/没用），不受是否解决影响。
  - 可执行性（最多 12 分）：建议是否给出可直接执行的步骤/文件/命令/验证方式。
  - 幻觉风险（最多 10 分）：只判断凭空编造的事实/API/引用/结论；完成声明无证据归「问题解决」。

## 六、问题排查路径
- 路径 A（大盘 P95 飙升 → 定位 session）：大盘看 P95 异常 → 下拉「高风险 session 表」（健康度升序，异常 chip 列是分诊单）→ 点 session id 进明细看 5 维雷达。
- 路径 B（异常标签飙红 → 找共性）：异常菜单看 sparkline 上升 → 抽查 2–3 个命中 session → 在 DAG 里定位失败 span，看是否共用同一工具/输入/Agent 版本。
- 路径 C（单 session 健康度<50 → 找根因）：5 维雷达找最低维 → DAG 定位关键路径（橙色高亮）→ 读「执行分析」事件流（红色事件是断点）→ 交叉读「异常清单」+「质量评估」。
- 排查心法：先看分布再看个体（大盘→异常→明细）；哪一维独凹下去先查哪一维；关键路径优先；规则信号 ∩ LLM 信号交叉验证。

## 七、术语对照
- Session=一次完整对话(OTel root trace)；Turn=对话轮次(user→assistant 消息对)；Step=执行步数(1 LLM call + 紧随 tool calls)；Span=步骤埋点(OTel 最小单元)；DAG=执行流程图(父子 span 有向无环图)；Critical Path=关键路径(最长串行链)；OTel=OpenTelemetry 埋点协议；failed_label=异常标签；max_serial_run=最长连续相同工具调用。

## 八、常见问答
- 总成本与财务账单对不上：平台用 $1.5/1M token 简化估算，不区分 input/output 单价，非财务真账。
- 某 session 没有 DAG：OTel 上报残缺（只有 root span 无子 span），通常埋点版本不一致或日志被截断。
- 健康度 ≥85 是否万事大吉：不一定，综合分可能被某些维度拉高，应同时看 5 维雷达形状，明显凹陷维度值得关注。
